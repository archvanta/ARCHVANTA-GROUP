# ARCHVANTA AI COMPANY OS

کنسول عملیاتی فارسی و راست‌چین ARCHVANTA GROUP. مدیرعامل انسانی تصمیم‌های مهم را بررسی می‌کند، رئیس دفتر و مدیر عملیات هوش مصنوعی کارها را میان مدیران هماهنگ می‌کند، و مدیران دپارتمان مسئول کیفیت و تحویل خروجی تخصصی‌اند.

دو محیط از همین مخزن ساخته می‌شوند. [دفتر سه‌بعدی عمومی](https://archvanta.github.io/ARCHVANTA-GROUP/office.html) از داده‌های نمونه و تصمیم‌های همان مرورگر استفاده می‌کند. دفتر خصوصی کارها، زمان‌بندی، پیش‌نویس متخصص، بازبینی مدیر، بستهٔ تصمیم رئیس دفتر و تصمیم مدیرعامل را در پایگاه داده ذخیره می‌کند.

## اجرا و بررسی محلی

به Node.js 24 یا بالاتر نیاز است. وابستگی مرورگر همراه سورس است. در ریشهٔ مخزن اجرا کنید.

```sh
node --test
node scripts/build.mjs
node scripts/preview.mjs
```

نشانی پیش‌نمایش [http://127.0.0.1:4173/ARCHVANTA-GROUP/](http://127.0.0.1:4173/ARCHVANTA-GROUP/) است. قرار دادن سایت در این مسیر، حالت معمول یک پروژهٔ GitHub Pages را بازسازی می‌کند.

برای بررسی دستی، صف تصمیم‌ها را باز کنید. یک مورد را تأیید کنید و برای دو مورد دیگر رد و درخواست اصلاح را با دلیل امتحان کنید. شمارندهٔ صف کم می‌شود و وضعیت کارها به «آمادهٔ اجرا»، «رد شده» و «نیازمند اصلاح» تغییر می‌کند. سوابق را باز و صفحه را بازخوانی کنید. یک پنجرهٔ خصوصی تازه برای تکرار سناریو با وضعیت اولیه کافی است.

## اجرای دفتر خصوصی

برای راه‌اندازی روی همین دستگاه، یک سرور مدل محلی سازگار با Chat Completions (مانند [llama.cpp](https://github.com/ggml-org/llama.cpp/tree/master/tools/server)) را روی آدرس loopback اجرا کنید. `MODEL_ALIAS` را با نامی که سرور مدل می‌پذیرد جایگزین کنید.

```sh
node scripts/build.mjs
node scripts/prepare-private.mjs http://127.0.0.1:4311/v1 MODEL_ALIAS
node --env-file=.env.local server/start.mjs
```

دفتر روی [http://127.0.0.1:4310/](http://127.0.0.1:4310/) است. کلید تصادفی `ARCHVANTA_CEO_KEY` در `.env.local` همان دستگاه است. ساخت تنظیمات موجود را جایگزین نمی‌کند. این فایل، داده‌های `.runtime/` و تنظیمات اجرای مدل در خروجی عمومی قرار نمی‌گیرند. بدون مدل، ورود و ساخت اتاق در دسترس‌اند و ارسال کار در انتظار تنظیم مدل می‌ماند.

برای میزبانی دائمی، برنامه را با Node.js 24، فضای دیسک پایدار و پراکسی HTTPS اجرا کنید. `ARCHVANTA_ORIGIN` باید نشانی HTTPS دفتر باشد و پراکسی باید هدر `Host` را حفظ کند. به‌صورت پیش‌فرض سرور فقط روی همین دستگاه گوش می‌دهد. برای مخزن اسرار میزبان از `ARCHVANTA_CEO_KEY` و در صورت نیاز `ARCHVANTA_MODEL_API_KEY` استفاده کنید. `ARCHVANTA_DB` مسیر SQLite روی دیسک پایدار و `ARCHVANTA_MODEL_URL` و `ARCHVANTA_MODEL` تنظیمات مدل‌اند. زمان‌بند همراه فرایند سرور اجرا می‌شود. در زمان خاموشی، درخواست‌ها در دیسک می‌مانند و اجرا پس از روشن شدن از سر گرفته می‌شود.

### اولین گردش واقعی

به یک اتاق بروید و محدوده و معیار کیفیت یک پیش‌نویس داخلی را بنویسید. متخصص پیش‌نویس، مدیر بازبینی و رئیس دفتر بستهٔ تصمیم تولید می‌کند. با انتخاب «نیازمند تأیید مدیرعامل»، خروجی برای تصمیم در صف می‌ماند. با تأیید، خروجی داخل دفتر آماده می‌شود. درخواست اصلاح، امکان ارسال نسخهٔ متصل به تصمیم قبلی را فراهم می‌کند. «زمان‌بندی اجرا» زمان دستگاه را برای ورودی می‌پذیرد و زمان‌های ثبت‌شده در دفتر را به وقت تهران نمایش می‌دهد. گزینهٔ توقف صف از شروع کار تازه جلوگیری می‌کند.

## انتشار نسخهٔ عمومی

گردش‌کار GitHub Actions روی Pull Request و `main` آزمون مدل و خروجی قابل انتشار را بررسی می‌کند. روی `main` و اجرای دستی از همین شاخه، پس از موفقیت بررسی‌ها فقط `dist/` منتشر می‌شود. در تنظیمات مخزن، منبع Pages باید روی **GitHub Actions** باشد. نشانی انتشار از خروجی job `deploy` مشخص می‌شود. [راهنمای GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

GitHub Pages برای فایل‌های استاتیک دمو است. این سرویس بک‌اند اجرایی دائمی، پایگاه داده، صف، زمان‌بند یا محل امن نگهداری کلید API فراهم نمی‌کند. فایل‌های خروجی برای بازدیدکننده قابل خواندن‌اند. دفتر عملیاتی با پایگاه داده و اسرار در فرایند جداگانه اجرا می‌شود. [محدودیت‌های GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)
